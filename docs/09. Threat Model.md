# MÔ HÌNH PHÂN TÍCH RỦI RO & BẢO MẬT (THREAT MODEL) - SECURE VAULT MANAGER (SVM)

---

## 1. Giới Thiệu & Mục Đích

Tài liệu Mô hình Đe dọa (Threat Model) này thiết lập ranh giới tin cậy, phân tích các bề mặt tấn công chính và ghi nhận trung thực **các biện pháp bảo vệ đã triển khai** cũng như **giới hạn thực tế** của **Secure Vault Manager (SVM)**.

---

## 2. Giả Định Môi Trường & Ranh Giới Tin Cậy (Trust Boundaries)

### 2.1. Giả Định Căn Bản

- **Thiết bị phần cứng và Kernel hệ điều hành cơ bản là tin cậy:** Nếu máy trạm bị nhiễm malware cấp kernel/root hoặc keylogger phần cứng, không ứng dụng user-space nào có thể bảo vệ tuyệt đối.
- **Cô lập theo tài khoản người dùng OS:** Dựa vào phân quyền tệp `0o600` (trên Unix) và phân tách thư mục dữ liệu người dùng của hệ điều hành.

### 2.2. Sơ Đồ Ranh Giới Tin Cậy

```text
[ INTERNET / MẠNG KHÔNG TIN CẬY ]
   |  (Không đồng bộ đám mây; chỉ kết nối mạng khi người dùng chủ động bật tải Favicon)
   v
[ BROWSER CONTEXT ]
   Trang Web Độc Hại (Phishing / XSS / Script giả mạo)
      |  (Ranh giới 1: MAIN World DOM vs ISOLATED World Content Script & Shadow DOM)
   Extension Context (Background Service Worker MV3)
      |  (Ranh giới 2: Chrome/Firefox Native Messaging API - chrome.runtime / stdio)
[ OPERATING SYSTEM PROCESS CONTEXT ]
   svm-native-host (Relay nhị phân)
      |  (Ranh giới 3: IPC Socket / Windows Named Pipe cục bộ)
   svm (Tiến trình Desktop chính: Qt6 UI + libsvm_core)
      |  (Ranh giới 4: User Space RAM [mlock + zeroize] vs Local Disk)
[ LOCAL FILE SYSTEM ]
   <DATA_DIR>/vault.svm, biometric.env, attachments/*.bin
```

## 3. Phân Tích Mối Đe Dọa Theo Mô Hình STRIDE

### 3.1. Giả Mạo Định Danh (Spoofing)

| Rủi ro | Kịch bản tấn công | Biện pháp hiện tại & Lưu ý thực tế |
| :--- | :--- | :--- |
| **Lạm dụng Native Messaging từ Extension lạ** | Extension không phải của SVM cố gọi `svm-native-host`. | Manifest Native Messaging (`io.hephaestus.secure_vault_manager.json`) giới hạn danh sách `allowed_origins` (Chrome/Edge/Brave) và `allowed_extensions` (Firefox). |
| **Giả mạo Trang web / Phishing (Autofill & Passkey)** | Trang web khác nguồn gốc hoặc trang web chèn iframe độc hại cố lấy credential/Passkey. | 1. Extension trích xuất `origin` từ `sender.url` do trình duyệt cung cấp.<br/>2. Autofill chỉ kích hoạt theo lựa chọn trên overlay/popup hoặc khi khớp domain.<br/>3. Passkey khớp theo `rpId` (`matches_passkey_rp_id`) và yêu cầu xác nhận trên modal Shadow DOM (`#svm-passkey-modal-host`, `mode: "closed"`).<br/>*Giới hạn:* Hiện tại `svm-webauthn` khớp hậu tố theo dấu chấm mà chưa dùng Public Suffix List (PSL) đầy đủ. |
| **Client SSH Agent ký trái phép** | Tiến trình người dùng gọi `SSH_AUTH_SOCK` yêu cầu ký challenge bí mật. | Khi bật `ssh_prompt_approval` (mặc định bật), Desktop App hiển thị `NotificationDialog::question` với thời gian chờ 30 giây trước khi ký. Nếu tắt `ssh_prompt_approval` hoặc người dùng bấm đồng ý, agent thực hiện ký Ed25519. *(Hiện chưa kiểm tra PID/ExePath client qua `SO_PEERCRED`).* |
| **Tiến trình cục bộ kết nối IPC Bridge** | Tiến trình khác cùng UID kết nối trực tiếp vào `bridge.sock`. | Socket đặt trong `$XDG_RUNTIME_DIR/svm/` (hoặc thư mục dữ liệu người dùng quyền `0o600` trên Unix). *(Hiện chưa triển khai handshake mật mã X25519 hay kiểm tra `SO_PEERCRED` trên `svm-bridge`).* |

### 3.2. Can Thiệp Trái Phép (Tampering)

| Rủi ro | Kịch bản tấn công | Biện pháp hiện tại & Lưu ý thực tế |
| :--- | :--- | :--- |
| **Sửa đổi tệp `vault.svm` hoặc `.bin` trên đĩa** | Kẻ tấn công chỉnh sửa byte trong payload vault hoặc chunk đính kèm. | 1. Payload chính và từng chunk attachment mã hóa xác thực bằng **ChaCha20-Poly1305 AEAD** với AAD riêng theo ngữ cảnh (`svm-master-dek-v1`, `svm-recovery-dek-v1`, `svm-vault-payload-v1`, `svm-attachment-v1 | | chunk_idx`).<br/>2. Mọi thay đổi byte trên ciphertext hoặc tag xác thực làm giải mã thất bại ngay.<br/>*Lưu ý:* 169 byte header`SVM1` không nằm trong `AAD_PAYLOAD` tĩnh, nhưng sai lệch salt/nonce/wrapped DEK sẽ làm giải mã `DEK` hoặc payload thất bại ngay tại Poly1305 tag check. |
| **Nghe trộm nội dung DOM của Passkey Modal** | JavaScript độc hại trên trang web đọc hoặc bấm hộ nút xác nhận Passkey trong trang. | Modal phê duyệt Passkey (`passkey_modal.ts`), overlay autofill (`overlay.ts`) và khung crop QR (`crop-overlay.ts`) được cô lập trong **closed Shadow DOM**. Giao tiếp `window.postMessage` từ MAIN world đi qua content script trước khi tới Background Service Worker. |

### 3.3. Chối Bỏ Trách Nhiệm / Mất Dữ Liệu (Repudiation & Data Loss)

| Rủi ro | Kịch bản tấn công | Biện pháp hiện tại |
| :--- | :--- | :--- |
| **Ghi đè hoặc xóa nhầm mật khẩu** | Người dùng sửa nhầm hoặc xóa mục quan trọng. | 1. Mỗi lần `upsert_item` ghi đè mục cũ, `svm-vault` tự động lưu snapshot vào `ItemRevision` (tối đa **20 bản gần nhất**).<br/>2. Xóa thông thường chuyển vào Thùng rác (`trashed: true`) kèm xác nhận `ConfirmDeleteDialog`.<br/>3. Ghi tệp qua tệp tạm `.tmp` (`0o600`) rồi `fs::rename` giúp hạn chế hỏng tệp dở dang khi ghi. |

### 3.4. Tiết Lộ Thông Tin (Information Disclosure)

| Rủi ro | Kịch bản tấn công | Biện pháp hiện tại |
| :--- | :--- | :--- |
| **Đọc khóa DEK từ Swap / Paging** | Hệ điều hành đẩy trang nhớ RAM chứa `DEK` xuống đĩa swap. | `svm-crypto/src/mem.rs` gọi `mlock` (Unix) / `VirtualLock` (Windows) cho buffer chứa `DEK` trong `VaultService`, và `munlock` + `zeroize` khi khóa kho. |
| **Đọc RAM qua Core Dump hoặc Attach** | Lỗi crash sinh core dump hoặc tiến trình cùng user đọc memory. | `svm_harden_process()` (`svm-system/src/hardening.rs`) thiết lập `prctl(PR_SET_DUMPABLE, 0)` trên Linux và `ptrace(PT_DENY_ATTACH)` trên macOS khi khởi động ứng dụng. |
| **Rò rỉ qua Clipboard History** | Phần mềm quản lý clipboard lưu lại mật khẩu/2FA vừa sao chép. | 1. `ClipboardManager` tự động xóa clipboard sau `clipboard_clear_seconds` (mặc định 30s) và hỗ trợ `clear_clipboard_on_lock`.<br/>2. Gắn hint MIME ẩn trên Linux (`x-kde-passwordManagerHint` = `"secret"`), Windows clipboard flags và macOS NSPasteboard concealed type. |
| **Rò rỉ danh sách dịch vụ qua Favicon** | Tự động gửi request DNS/HTTP cho toàn bộ domain trong Vault. | Tính năng tải Favicon (`svm_favicon_fetch` qua `ureq`) là **Opt-in**, mặc định **TẮT** cho đến khi người dùng bật trong Settings. |
| **Lộ mật khẩu trên JSON danh sách** | Hiển thị danh sách thẻ làm tràn plaintext secret vào model Qt. | `svm_items_list` trả về bản ghi tóm tắt (loại bỏ `password`, `totpSecret`, `notes`, `cardNumber`, `cardCvv`, `customFields`); plaintext chỉ được nạp khi mở chi tiết item (`svm_item_get`) hoặc qua `svm_item_reveal_field` kèm `svm_free_secret()` zeroize. |

### 3.5. Từ Chối Dịch Vụ (Denial of Service)

| Rủi ro | Kịch bản tấn công | Biện pháp hiện tại |
| :--- | :--- | :--- |
| **Tràn RAM do tệp đính kèm hoặc gói IPC lớn** | Đính kèm file dung lượng lớn hoặc gửi frame IPC quá khổ. | 1. Attachments mã hóa/giải mã theo luồng từng chunk **64 KiB** (`SVMA`).<br/>2. `svm-native-host` giới hạn kích thước frame stdio (`4 MB` inbound, `10 MB` outbound) và `svm-ipc` giới hạn frame socket tối đa `16 MB`. |
| **Treo UI hoặc Panic xuyên qua FFI** | Lỗi nội bộ Rust làm sập tiến trình Qt C++. | Các hàm CRUD item và một số hàm quản trị vault bọc `catch_unwind` (`ffi_guard`) trả về mã lỗi `SVM_ERR_PANIC` (99). |

## 4. Giới Hạn & Những Điều SVM Không Bảo Vệ (Explicit Non-Goals & Current Limitations)

1. **Thiết bị đã bị chiếm quyền Root / Administrator hoặc nhiễm Kernel Malware:** Nếu kẻ tấn công có đặc quyền quản trị hoặc nạp driver độc hại, ứng dụng user-space không thể ngăn đọc RAM hay ghi thao tác bàn phím.
2. **Trạng thái Hibernate (Ngủ đông ra đĩa):** Toàn bộ RAM vật lý được OS chép xuống đĩa khi Hibernate; người dùng nên bật **Khóa khi máy ngủ (Lock on Sleep)** (hỗ trợ qua `gdbus` trên Linux) và tự động khóa theo thời gian nhàn rỗi.
3. **Biến cố cùng UID trên Unix Desktop:** Trong chế độ mặc định phiên Desktop đang mở khóa, khóa `biometric.env` lưu trong OS Keyring phụ thuộc vào ranh giới bảo mật của keyring phiên đăng nhập người dùng; đồng thời IPC `svm-bridge` và `svm-ssh-agent` hiện chưa kiểm tra peer executable qua `SO_PEERCRED`.
4. **Bộ nhớ nội bộ của Qt Widgets & Input Method (IME):** Các widget nhập văn bản chuẩn Qt (`QLineEdit`) hoặc bộ gõ hệ thống (IBus, Fcitx) có thể lưu bản sao chuỗi ký tự trong bộ nhớ tạm trước khi đóng dialog.
5. **Tấn công kênh kề phần cứng (Side-Channel Attacks):** Spectre, Meltdown, Rowhammer nằm ngoài phạm vi phòng vệ của ứng dụng Desktop.
