# ĐẶC TẢ ĐỊNH DẠNG TỆP TIN VAULT - SECURE VAULT MANAGER (SVM)

---

## 1. Cấu Trúc Thư Mục Kho Dữ Liệu (Vault Directory Layout)

Để đáp ứng khả năng lưu trữ các tệp đính kèm lớn (Attachments), lịch sử phiên bản (Item History) và snapshot sao lưu tức thời, mỗi Vault được cấu trúc thành một **thư mục độc lập** trong vùng dữ liệu người dùng (`$XDG_DATA_HOME/secure-vault-manager/vaults/<vault_id>/` trên Linux, `%LOCALAPPDATA%\secure-vault-manager\vaults\<vault_id>\` trên Windows, hoặc `~/Library/Application Support/secure-vault-manager/vaults/<vault_id>/` trên macOS):

```text
vaults/<vault_id>/
├── vault.svm               # Tệp nhị phân chính: Chứa Header, KDF params, Wrapped DEK và Ciphertext các Items
├── vault.svm.lock          # File lock tránh xung đột khi có nhiều tiến trình mở đồng thời
├── attachments/            # Thư mục lưu trữ các tệp đính kèm đã được mã hóa riêng biệt
│   ├── <attachment_id>.blob
│   └── ...
└── backups/                # Thư mục chứa các snapshot sao lưu tự động xoay vòng
    ├── vault.20261103_165000.svm
    └── ...
```

## 2. Đặc Tả Nhị Phân Tệp `vault.svm`

Tệp `vault.svm` được tổ chức thành 2 phân vùng rõ rệt: **Unencrypted Header** (siêu dữ liệu cần thiết để phục vụ KDF giải mã) và **Encrypted Payload** (chứa toàn bộ cơ sở dữ liệu các mục lưu trữ).

```text
+-------------------------------------------------------------------------+
| UNENCRYPTED HEADER (Biến thiên độ dài, tối thiểu 96 bytes)             |
+-------------------------------------------------------------------------+
| Magic Bytes: "SVM1" (4 bytes ASCII: 0x53, 0x56, 0x4D, 0x31)             |
| Format Version: 0x0001 (2 bytes uint16 little-endian)                  |
| Flags: (2 bytes bitmask: Bit 0 = Biometric Wrapped, Bits 1-15 Reserved)|
| Salt: 16 bytes ngẫu nhiên từ CSPRNG                                     |
+-------------------------------------------------------------------------+
| KDF Parameters Block (Argon2id) (12 bytes)                              |
|   - Memory Size (m_cost): uint32 little-endian (ví dụ: 65536 = 64MiB)   |
|   - Iterations (t_cost): uint32 little-endian (ví dụ: 3)                |
|   - Parallelism (p_cost): uint32 little-endian (ví dụ: 4)               |
+-------------------------------------------------------------------------+
| Wrapped DEK Envelope Block (56 bytes)                                   |
|   - Envelope Nonce: 12 bytes ngẫu nhiên (ChaCha20-Poly1305)             |
|   - Encrypted DEK: 32 bytes (Data Encryption Key)                       |
|   - Poly1305 Tag: 16 bytes Authentication Tag                           |
+-------------------------------------------------------------------------+
| Payload Metadata (16 bytes)                                             |
|   - Payload Nonce: 12 bytes ngẫu nhiên                                  |
|   - Reserved: 4 bytes (0x00000000)                                      |
+-------------------------------------------------------------------------+
| ENCRYPTED PAYLOAD (Độ dài N bytes)                                      |
+-------------------------------------------------------------------------+
| Ciphertext: Dữ liệu JSON danh sách VaultItem nén Zstandard (zstd)       |
| Poly1305 Authentication Tag: 16 bytes cuối cùng                         |
+-------------------------------------------------------------------------+
```

### Cơ Chế Xác Thực Associated Data (AAD)

Khi thực hiện mã hóa và giải mã khối Payload, toàn bộ các byte từ đầu tệp đến hết phần Payload Metadata (toàn bộ Unencrypted Header) được sử dụng làm **Associated Data (AAD)** trong thuật toán AEAD ChaCha20-Poly1305. Bất kỳ sự thay đổi trái phép nào đối với Magic Bytes, Salt, KDF Parameters hoặc Wrapped DEK đều khiến quá trình giải mã Payload thất bại ngay lập tức trước khi phân tích cú pháp dữ liệu.

## 3. Đặc Tả Tệp Đính Kèm An Toàn (`attachments/*.blob`)

Các tệp đính kèm có thể có dung lượng từ vài KB đến 50MB. Để tối ưu hóa bộ nhớ RAM và bảo mật tối đa:

1. Mỗi tệp đính kèm được sinh một khóa riêng **Attachment Key (AK)** ngẫu nhiên 32 bytes.
2. Khóa AK được mã hóa bằng **DEK** và lưu trữ dưới dạng siêu dữ liệu trong thuộc tính của `VaultItem`.
3. Bản thân nội dung tệp được mã hóa theo giao thức **STREAM AEAD** (chia thành từng chunk 64 KiB) sử dụng thuật toán ChaCha20-Poly1305:

```text
+-------------------------------------------------------------------------+
| ATTACHMENT BLOB HEADER (16 bytes)                                       |
+-------------------------------------------------------------------------+
| Magic Bytes: "SVMB" (4 bytes)                                           |
| Chunk Size: 0x00010000 (4 bytes = 65536 bytes)                          |
| Base Nonce: 8 bytes ngẫu nhiên                                          |
+-------------------------------------------------------------------------+
| STREAM CHUNKS (Mỗi chunk = 64KiB plaintext + 16 bytes Tag)              |
+-------------------------------------------------------------------------+
| Chunk 0: Encrypted Data (64 KiB) + Tag (16 bytes)                       |
| Chunk 1: Encrypted Data (64 KiB) + Tag (16 bytes)                       |
| ...                                                                     |
| Final Chunk: Encrypted Data (<= 64 KiB) + Tag (16 bytes, Final Flag)    |
+-------------------------------------------------------------------------+
```

Lợi ích: Tránh việc phải nạp toàn bộ tệp 50MB vào RAM cùng một lúc khi đọc hoặc ghi.
