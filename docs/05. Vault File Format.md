## 1. Cấu Trúc Thư Mục Dữ Liệu (`<DATA_DIR>`)

Toàn bộ dữ liệu kho lưu trữ của người dùng được lưu phẳng (flat layout) tại thư mục dữ liệu cấu hình bởi `svm-storage/src/atomic.rs`:

- Có thể ghi đè qua biến môi trường `SVM_DATA_DIR`.
- **Linux:** `$XDG_DATA_HOME/hephaestus/secure-vault-manager` hoặc `$HOME/.local/share/hephaestus/secure-vault-manager`.
- **Windows:** `%APPDATA%\Hephaestus\SecureVaultManager`.
- **macOS:** `$HOME/Library/Application Support/Hephaestus/SecureVaultManager`.

```text
<DATA_DIR>/
├── vault.svm                  # Tệp nhị phân chính: Header 169B + Ciphertext ChaCha20-Poly1305
├── biometric.env              # (Tùy chọn) Phong bì 64B phục vụ mở khóa sinh trắc học
├── settings.json              # Cấu hình ứng dụng (theme, language, auto-lock, v.v.)
├── bridge_clients.json        # Danh sách Browser Extension client đã ghi nhận
├── attachments/               # Thư mục lưu tệp đính kèm mã hóa streaming
│   ├── <attachment_id>.bin
│   └── ...
└── favicons/                  # Bộ đệm icon website đã tải (nếu người dùng bật Favicon Fetch)
    └── <host>.bin
```

## 2. Đặc Tả Nhị Phân Tệp `vault.svm` (Dual-Wrapped Envelope Header)

Tệp `vault.svm` (`core/crates/svm-storage/src/header.rs` & `vault_file.rs`) gồm **Header 169 bytes** ở dạng rõ và **Encrypted Payload** mã hóa bằng AEAD **ChaCha20-Poly1305** (RFC 8439):

```text
+-------------------------------------------------------------------------+
| UNENCRYPTED DUAL-WRAPPED HEADER (Cố định 169 bytes)                     |
+-------------------------------------------------------------------------+
| Magic Bytes: "SVM1" (4 bytes ASCII: 0x53, 0x56, 0x4D, 0x31)             |
| Format Version: 0x01 (1 byte uint8)                                     |
+-------------------------------------------------------------------------+
| Master Password Envelope Block (76 bytes)                               |
|   - Master Salt: 16 bytes ngẫu nhiên từ CSPRNG                          |
|   - Master Nonce: 12 bytes ngẫu nhiên (ChaCha20-Poly1305)               |
|   - Master Wrapped DEK: 48 bytes (32B Encrypted DEK + 16B Poly1305 Tag) |
+-------------------------------------------------------------------------+
| Recovery Key Envelope Block (76 bytes)                                  |
|   - Recovery Salt: 16 bytes ngẫu nhiên từ CSPRNG                        |
|   - Recovery Nonce: 12 bytes ngẫu nhiên (ChaCha20-Poly1305)             |
|   - Recovery Wrapped DEK: 48 bytes (32B Encrypted DEK + 16B Tag)        |
+-------------------------------------------------------------------------+
| Payload Nonce (12 bytes)                                                |
|   - Payload Nonce: 12 bytes ngẫu nhiên dùng cho AEAD Payload            |
+-------------------------------------------------------------------------+
| ENCRYPTED PAYLOAD (N bytes)                                             |
+-------------------------------------------------------------------------+
| Ciphertext: JSON { vaults, items, revisions, attachments, trash }       |
| Poly1305 Authentication Tag: 16 bytes cuối cùng                         |
+-------------------------------------------------------------------------+
```

### 2.1. Dẫn Xuất Khóa (KDF) & Domain-Separated AAD

- **KDF (`svm-crypto/src/kdf.rs`):** `PBKDF2-HMAC-SHA256` với `100,000` vòng lặp tạo `KEK` 32 byte từ Password hoặc Recovery Key + Salt 16 byte.
- **AAD theo ngữ cảnh (Domain-Separated AAD strings):**
  - Phong bì Master DEK: `b"svm-master-dek-v1"`
  - Phong bì Recovery DEK: `b"svm-recovery-dek-v1"`
  - Payload chính: `b"svm-vault-payload-v1"`
- **Đặt lại Master Password không mất dữ liệu:** Khi mở khóa bằng Recovery Key, `svm-storage` giải mã `DEK` từ khối `Recovery Wrapped DEK`, sau đó dẫn xuất `Master KEK` mới và ghi lại khối `Master Wrapped DEK` mà không cần mã hóa lại các bản ghi hay tệp đính kèm.

### 2.2. Phong Bì Sinh Trắc Học (`biometric.env` — 64 bytes)

Tệp `biometric.env` nằm cùng cấp với `vault.svm` (`vault_file.rs` L304-378):

```text
+-------------------------------------------------------------------------+
| BIOMETRIC ENVELOPE (Cố định 64 bytes)                                   |
+-------------------------------------------------------------------------+
| Magic Bytes: "SVMB" (4 bytes ASCII)                                     |
| Nonce: 12 bytes ngẫu nhiên từ CSPRNG                                    |
| Wrapped DEK: 48 bytes (32B Encrypted DEK + 16B Poly1305 Tag)            |
+-------------------------------------------------------------------------+
```

1. Khi kích hoạt `svm_vault_biometric_enable`, hệ thống sinh **Biometric Wrapping Key (BWK)** 32 byte ngẫu nhiên và lưu vào OS Keyring (`keyring` crate, service `"io.hephaestus.secure-vault-manager"`, account `"biometric-wrapping-key::<sha256_prefix>"`).
2. `DEK` được bọc bằng `BWK` với ChaCha20-Poly1305 và `AAD = b"svm-biometric-dek-v1"` rồi ghi vào `biometric.env`.
3. Việc bật/tắt sinh trắc học chỉ tạo hoặc xóa `biometric.env` + key trong OS Keyring mà không làm biến đổi tệp `vault.svm`.

## 3. Đặc Tả Tệp Đính Kèm An Toàn (`attachments/<attachment_id>.bin`)

Tệp đính kèm (`vault_file.rs` L380-611) được mã hóa phân đoạn từng chunk **64 KiB** bằng trực tiếp khóa `DEK` của kho:

```text
+-------------------------------------------------------------------------+
| ATTACHMENT HEADER (8 bytes)                                             |
+-------------------------------------------------------------------------+
| Magic Bytes: "SVMA" (4 bytes ASCII)                                     |
| Chunk Size: 65536 (4 bytes uint32 Little-Endian = 0x00010000)           |
+-------------------------------------------------------------------------+
| ENCRYPTED CHUNKS (Lặp theo từng chunk)                                  |
+-------------------------------------------------------------------------+
| Chunk N:                                                                |
|   - ct_len: 4 bytes uint32 Little-Endian (0 = Sentinel kết thúc tệp)    |
|   - Nonce: 12 bytes ngẫu nhiên từ CSPRNG                                |
|   - Ciphertext + 16 bytes Poly1305 Tag                                  |
+-------------------------------------------------------------------------+
```

- **Xác thực AAD của mỗi chunk thứ `i`:** `AAD = b"svm-attachment-v1" || chunk_idx.to_le_bytes()` (với `chunk_idx` là `uint32` hoặc `uint64` little-endian tăng dần từ `0`).
- Stream kết thúc bằng block đánh dấu độ dài `ct_len = 0u32` (4 byte 0).

## 4. Quy Trình Ghi Tệp Nguyên Tử & Reset Kho (`atomic.rs`, `vault_file.rs`)

1. **Ghi nguyên tử (`atomic_write_file`):**
   - Ghi toàn bộ dữ liệu ra tệp tạm `<path>.tmp`.
   - Trên hệ điều hành Unix, gán quyền hạn tệp `0o600` (chỉ chủ sở hữu được đọc/ghi).
   - Thực hiện `fs::rename` đè nguyên tử lên `<path>`.
2. **Reset kho (`svm_vault_reset` / `backup_and_reset_vault`):**
   - Di chuyển tệp `vault.svm` hiện tại sang `vault.svm.abandoned.<timestamp>`, xóa `biometric.env` và thư mục `attachments/`.
